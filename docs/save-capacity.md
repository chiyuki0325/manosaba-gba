# 存档容量与实现

## 当前结论与边界

2026-11-23：**32 KiB SRAM 可以按固定字段方案容纳 8 手动＋1 自动＋1 重试，并保留每个槽自己的重试起点、写入备份和双份全局状态。**

生产写入器的正文长度固定为 **1254 B**。普通槽按现有 64 B 文件头、192 B 目录，并附带另一份完整 1254 B 重试起点计算：`256 + 1254 + 1254 = 2764 B < 3072 B`。这个上界不依赖压缩率、台词长度、路径是否同时达到各字段最大值或小坐标假设。

**已接入生产VM、写入器、旧Flash迁移和网页转换。** 新写入统一使用固定字段格式5；仅兼容已发布的Flash格式3，未发布的SRAM格式4不作为迁移目标。

Flash已扩为27手动＋1自动＋1重试；SRAM保留8手动＋1自动＋1重试。两种后端共享同一正文与恢复语义，存储布局分别实现。

## 为什么能装下

现有快照把文本、选项、候选、异议返回文字、分页、图鉴窗口位置、淡变参数等也写进去；它们有些会随文本长度增长，有些会残留到下一种界面。旧实现的 varint 数值还会随坐标／ID／计时大小增长，不能只量一条路线就保证全游戏上界。

新方案先删除可重建的数据，再直接用固定宽度小端编码。所有舞台属性保留完整 `int32_t`，不截断坐标，不压缩动画图像，也不需要为了控制档案大小修改演出。

| 正文部分 | 固定字节 | 内容 |
| --- | ---: | --- |
| 当前位置 | 9 | 1 B 执行标志、32位 script、32位 source_pc |
| 分支语义 | 12 | flags、area、direct、完整64位 trial_flags |
| 审判与选择结果 | 16 | HP、bad_id、总倒计时、chosen_item，各32位 |
| 图鉴剧情版本 | 169 | 168条版本＋章节；这是证物候选／调查进度，不是窗口状态 |
| 当前法庭表现 | 56 | actor/view/picture/camera/duration各32位，17个16位姿态，layout、witch_hiro |
| 其他持久演出 | 10 | visual_frame、printer_style、reenact、reenact_scene、map_segment |
| 屏幕效果 | 9 | 4个16位目标分量＋court_fire；不保存渐变进度 |
| 异议返回 | 65 | valid、32位 script/source_pc、56 B返回前法庭表现 |
| 舞台 | 881 | 16 × (12 × 4 B属性＋image/order/mask各2 B＋表现位1 B)＋printer 1 B |
| 音乐 | 9 | key、脚本音量各32位，loop 1 B |
| 持续 SFX | 18 | 最多两条，每条cue/volume各32位、loop 1 B；空位cue=-1 |
| **合计** | **1254** | 不包含全局收集；全局独立保存 |

C++ struct 的 padding 不进入磁盘；不得改成 `memcpy(sizeof(struct))`。也不能把这些字段继续交给旧 varint archive，然后仍宣称是 1254 B。正式读写器按字段逐字节编码，并以全0、0x55、0xAA、全1构造数据往返，长度都相同。

这已经包含完整的返回元组、16个舞台实体、两路持续音，以及第二份同样大的重试正文。没有依赖“异议返回通常不会与地图／舞台一起出现”来减预算。无效返回块和空舞台实体也保留固定占位，优先减少代码分支。

## SRAM 布局

采用32 KiB物理区域，不需要扩大到64 KiB：

| 偏移 | 区域 | 新方案实际最大使用 |
| ---: | --- | ---: |
| 0–27647 | 8手动＋1自动，9 × 3072 B | 每页2764 B，余308 B |
| 27648–29183 | 重试，1536 B | 64 B头＋1254 B正文＝1318 B，余218 B |
| 29184–32255 | 共用写入备份，3072 B | 能装下最大的2764 B记录 |
| 32256–32767 | 两份全局，各256 B | 每份64 B头＋120 B全局＝184 B |

重试不在存读档列表展示，**不再写192 B摘要／缩略图ID／日期目录**。

手动档仍带自己的重试起点。不能为了省空间，读入旧手动档后把“重试”指到最近另一条路线的全局重试槽。共用备份和双全局保留，断电安全不能当作可删的冗余。

全局原本就是位图：已读脚本64 B、结局2 B、图鉴21 B、画廊20 B、音乐8 B，加设置／历史保留字节，共120 B；不会因解锁数量增长，也不复制到各手动槽。图鉴的168条版本不是布尔解锁，不能直接改为168个bit。

## Flash布局与旧档整理

0–122879为30个4 KiB扇区，容纳27手动＋自动＋重试的29条记录，并保留一个写入备用扇区；122880／126976为双份全局页。新记录只擦写一个扇区，旧记录占两个扇区。扫描目录时保护两扇区，槽位12／13／14从旧自动／重试／全局映射到新位置。

旧档仍可直接读取，新保存只写格式5。向空槽保存而备用空间不足时，先以纯字段转换器将一条旧记录及其附带重试写至备用扇区；CRC与提交成功后才能回收旧两扇区。这个过程不调用scene恢复、不执行VM、不动舞台或音频。旧槽和新槽混用时仍保留一个备用扇区；整个维护阶段对UI持续报告busy。

## 锚点与恢复语义

### 正常可停留节点

`source_pc` 指向 TLV 指令的**起始地址**，不是现有读取 payload 后的 `_pc`。异议打断时另记 `return_source_pc`。

恢复顺序：

1. 恢复分支变量、HP、总倒计时、图鉴版本、当前／返回法庭表现等语义字段。
2. 设置 script，丢弃解压缓存的旧块编号。
3. 纯 payload 解码器从 source_pc 读取当前 `say/debate/menu/trial_menu/inventory/pause/end/bad_end/title`。从ROM重建文本、姓名、讨论链接／布局／时长、选项、证物候选；不调用 `advance()` 或 `start()`，不重播音频、不重做加血／扣血／分支写入。
4. `_pc` 指到该条指令末尾。地图选项用已恢复flags过滤；证物／人物候选用已恢复book_versions生成。
5. 如果 return_valid，再从返回锚点解码讨论 payload；不要把当前恢复的文本覆盖成返回台词。返回的单句时长重置完整值，总倒计时保持已存剩余。
6. 绑定当前脚本对应的图形bank，再恢复一份共享舞台目标状态；ADV与Trial使用同一份 image_scene，不重复保存。法庭／地图／小剧场由各自语义ID重建。
7. 关闭图鉴、记录、暂停、详情预览；选项从首项开始。当前台词第1页完整显示，不恢复打字机或分页偏移。历史列表清空。
8. 图形提交完成后按cue从头播放音乐／持续音；保留已有读档过程中的画面与音频提交顺序，不在解码字段时直接播放。

### 方案中修正的两项遗漏

- **map_segment 必须保留。** 它不仅在地图入场动画时使用；`trial_player::draw()` 在后续文本仍用它请求当前地图段。丢弃会把读档画面错误恢复成法庭。恢复时地图结算到段末，不续插值进度。
- **chosen_item 保守保留4 B。** VM的 `test` 会读取它，且没有在文本节点清零。除非另行证明所有读取都在同一次 advance 内完成，否则不能把选择结果当作候选窗口状态删除。这不要求保存候选列表。

`music_alias`只是VM调试标签及自身的别名记账，不驱动播放器，不必持久化。重试种类可由script模式／源指令推导，不另存原来的snapshot kind。舞台的previous没有读取者，删除；播放指针、tracks、emotes、clock、wait也不存。

### 在瞬态演出中按暂停

不能把“上一句显示锚点＋已经变化的新舞台”拼成记录，加载后再从上一句重放后续命令。这会重复SFX、变量甚至扣血。仅增加显示锚点还不足以直接替换现有 archive。

1 B执行标志不是窗口状态：

- 位0：工作预算用尽时保存的是下一条待执行指令cursor。正常文本／菜单和异议返回均用anchor；cursor同时处理旧档中running/audio状态。
- 位1：当前yield的stage命令尚未应用。ADV的`_active_stage`及Trial的`_picture_event`区分了“VM已读到指令”和“舞台已应用指令”，不能把两者混同。保存时只取这一事实，不保存句柄、帧数或加载位置。

实施时按当前源opcode分类结算：音乐、屏幕渐变、镜头已经执行的部分只取目标，从当前指令末尾继续；舞台先按执行位决定是否补应用一次，再结算目标。title的TimeIsUp后续跳转、reenact关闭幕布、地图关闭仍需保留原指令语义，不能统一粗暴改成running。它们的参数可以从源指令读取，不再新增一堆动画状态字段。

小剧场幕布的开闭目标复用reenact字节中的一位，不保存动画帧进度。读取后关闭图鉴、历史、暂停、证物预览等覆盖界面；正文从第1页完整显示。

## 音频只取必要状态

- 音乐只存key／脚本音量／loop，从现有story入口重播，无播放坐标、PCM相位、淡变帧数。
- 按目标状态结算：停止中或目标音量0记为无曲；淡入目标非0时保留目标音量，不能因为当前帧音量恰好0就丢掉歌曲。
- 铃声下有待返回BGM时只保留原BGM，重放而不做快照续播；没有原BGM时按当前cue处理。无需另存第二首及恢复队列。
- SFX固定两个记录。优先保留实际发声且仍有效的持续音；短音占用声道时，从待继续的持续请求中按现有优先级补足两条。停止中／目标0、短音、淡变进度及六个内部stream结构不进入新档。超过两条持续请求不扩容，按同一优先级舍弃多余请求。
- 用户音乐／音效总音量仍在全局，不把退避时的临时混音增益烘进槽位音量。

## 旧档及转换页

Flash版兼容已发布格式3，新写入统一格式5；SRAM只读写格式5。旧文本／列表／历史／窗口／渐变进度只消费并丢弃，语义字段转入固定正文。`save_legacy.cpp`只转换字节，不恢复游戏场景，可同时用于读取与后台整理。

`save-converter.html`为无依赖单文件，自动识别Flash旧／新记录和SRAM，接受.sav／.srm，支持PC／移动端。Flash→SRAM可选8个手动槽，SRAM→Flash保留原8槽，另19槽为空；自动档、重试、设置、收集及时间戳一起迁移。原文件不变，输出不附加模拟器尾部数据。用户界面只显示存储类型，不显示内部版本号。

当前源内容中，say／debate／非地图菜单／inventory／pause／end／title可从post-PC和旧payload长度反推起点。地图菜单缺少隐藏项长度，由编译产物输出12项 `(script,end_pc)->start_pc` 表。幕布目标同样从编译字节码生成，网页和C++共享该输入；不依赖报告、原作文件或ROM。

`save_content_signature`不因存储编码升级而变化；字节码和资产编号未变。CRC或内容签名不符会拒绝读取／转换，不能静默截断剧情状态。旧92／112B全局前缀扩为120B，新收集位默认未解锁。

## 验证

- 生产VM固定346B、舞台881B、音频27B，正文1254B；编译断言保证最坏组合及附带重试可装入3 KiB页。
- `save_schema_probe.cpp`：411份脚本、165146条TLV、34799条显示指令、104385组payload对照；恢复不触发音频回调。
- `save_snapshot_test.cpp`：49707个ADV＋9714个Trial检查点往返、继续执行及旧VM锚点对照一致，舞台动画按目标姿态恢复。
- Flash／SRAM宿主写入器逐字节断电见证，包括全局双页、重试、SRAM备份归位、Flash旧两扇区迁移和27槽满目录。
- 实际mGBA：Flash27槽／SRAM8槽写入、RTC、冷读档、剧情锚点／画面、图鉴版本、审判总时间／HP、异议返回、TimeIsUp与重试；带真实音乐PCM。
- 实际旧Flash档及带重试的审判档，在Flash直接读和HTML转SRAM后读均通过；网页反向输出也经Flash ROM冷读。C++／网页独立转换的33份真实旧正文／重试逐字节一致。
- 满旧目录（12手动＋自动＋重试＋全局）上逐步填满27个手动槽，后台转换不改变当前剧情，保存过程有实际PCM输出。
- 浏览器在320px手机及1280px桌面宽度验证输入、重复选槽禁用、27槽映射、下载.sav／.srm及错误提示；无横向溢出，不显示内部格式版本。
- mGBA不等同PSP gpSP或实机烧录卡兼容性证明；后两者暂无设备实测。全剧情可达性与所有瞬态组合未穷举。

## 旧格式容量证据（历史）

旧格式曾测得普通ADV1095B、讨论1458B、异议选项1731B；这些采样不能证明全游戏上界。新实现不再依赖文本长度、varint压缩率或“通常不会同时出现”的状态组合，而直接用固定字段的构造上界。
